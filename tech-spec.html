РАЗДЕЛ 3

3. REST API Спецификация (OpenAPI 3.1)

Платформа предоставляет защищенный REST API с форматом ответов JSON и строгой валидацией типов:

GET /api/v1/hotels

Получение каталога объектов с поддержкой фильтрации по region, stars, model, iri_grade.

GET /api/v1/hotels/{id}/passport

Возвращает полный структурированный JSON инвестиционного паспорта (Том II) с вычисленными KPI и метаданными Data Room.

POST /api/v1/smartform/calculate

Принимает параметры отеля, выполняет калькуляцию USALI-показателей и возвращает интегральный скоринг IRI с детализацией по 6 критериям.

POST /api/v1/export/pdf/{hotel_id}

Запускает генерацию официального PDF-меморандума формата A4 (300 DPI) на выбранном языке (RU/UZ/EN).

РАЗДЕЛ 4

4. Алгоритмический калькулятор и скоринг IRI

Математическая модель расчета скоринга готовности $S_{\text{IRI}}$ вычисляется как взвешенная сумма баллов:

$$S_{\text{IRI}} = \sum_{i=1}^{6} (w_i \cdot c_i) = 0.20 \cdot c_{\text{fin}} + 0.20 \cdot c_{\text{law}} + 0.20 \cdot c_{\text{kpi}} + 0.15 \cdot c_{\text{ffe}} + 0.15 \cdot c_{\text{brand}} + 0.10 \cdot c_{\text{loc}}$$

где $c_i \in [0, 100]$ — балльная оценка по соответствующему критерию проверки. При значении $S_{\text{IRI}} \ge 90$ объекту автоматически присваивается высшая категория **A+ (Tier 1)**.

РАЗДЕЛ 5

5. Пайплайн генерации печатного паспорта (PDF)

Генерация печатного меморандума реализована на базе единой дизайн-системы токенов design-tokens.css. Рендеринг осуществляется без расхождений между веб-версией и печатным документом через @media print с принудительной разбивкой страниц A4.

РАЗДЕЛ 6

6. Безопасность и защищенный контур Data Room

Доступ к конфиденциальным аудированным финансовым отчетам и юридическим правоустанавливающим документам предоставляется инвесторам после верификации профиля и подписания цифрового соглашения о неразглашении (NDA). Все файлы в хранилище шифруются по стандарту AES-256 с динамическим водяным знаком (Watermark) инвестора.

РАЗДЕЛ 7 · ТОМ VIII

7. Модуль «Сертификация» (Том VIII · O'z DSt 3220:2017)

Подсистема электронной сертификации средств размещения разработана в соответствии с государственным стандартом O'z DSt 3220:2017 («Туристские услуги. Средства размещения. Общие требования») и ПКМ № 433 от 10.07.2020. Модуль реализует строгий принцип «One person — one decision»: персональное принятие решений инспектором ГУП «Центр сертификации туристских услуг» с подписанием личной ЭЦП E-IMZO, публичный онлайн-реестр и 5-летний инспекционный цикл.

7.2. Ролевая модель доступа (RBAC)

Архитектура безопасности разграничивает полномочия 4 ролей на уровне политик доступа API и пользовательских интерфейсов:

РольИнтерфейсКлючевые права и регламент
Заявитель (Отельер) certification-apply.html, cabinet-hotel.html Авторизация через OneID. Заполнение анкеты, загрузка фотодоказательств с геопривязкой, оплата госпошлины (Click/Payme), подписание оферты ЭЦП E-IMZO, отслеживание 9 шагов регламента.
Инспектор Центра cabinet-inspector.html (роль Инспектор) Единоличное рассмотрение заявок («One person — one decision»). Проверка чек-листа по 3 зонам (зеленая/желтая/красная), видеоинспекция в реальном времени, пакетное утверждение валидных позиций, подписание решения личной ЭЦП E-IMZO.
Руководитель Центра cabinet-inspector.html (роль Руководитель) Контроль соблюдения регламентных сроков (SLA 15 рабочих дней), мониторинг нагрузки экспертов, рассмотрение досудебных апелляций отельеров, аналитика отказов и риск-сигналов.
Администратор cabinet-inspector.html (роль Администратор) Управление версиями шаблона чек-листа (версионирование 2026.1), валидация целостности криптографической хеш-цепочки журнала аудита (SHA-256), мониторинг шины межведомственных интеграций.

7.3. REST API Спецификация подсистемы сертификации

RESTful эндпоинты модуля функционируют поверх единого хранилища данных и поддерживают строгие схемы валидации запросов:

GET /api/v1/cert/applications

Получение реестра заявок с фильтрацией по статусу (submitted, inspection), региону и заявляемой категории звездности.

POST /api/v1/cert/applications

Создание новой заявки отеля с первичными реквизитами, данными OneID и выбором категории.

PUT /api/v1/cert/applications/{id}/checklist

Обновление статусов пунктов чек-листа заявителем или экспертом (пакетное или точечное подтверждение соответствия).

POST /api/v1/cert/applications/{id}/evidence

Загрузка доказательства к пункту: вычисление SHA-256, dHash, проверка дисперсии Лапласиана (четкость) и Haversine-девиации координат (≤150м).

POST /api/v1/cert/applications/{id}/decision

Фиксация персонального решения инспектора («One person»), генерация электронного сертификата и запись в неизменяемый журнал аудита.

GET /api/v1/registry/certificates

Публичный реестр действующих сертификатов средств размещения с поддержкой геопоиска, фильтрации по звездам и статусам (active, suspended, expired).

GET /api/v1/registry/certificates/{number}

Точечная верификация сертификата по номеру (напр. UZ.TSM.TK.000123) для мгновенного QR-сканирования и отображения электронной копии.

GET /api/v1/cert/audit-log

Экспорт криптографического журнала аудита с проверкой непрерывности SHA-256 хеш-цепочки и детекцией несанкционированных изменений.

7.4. Межведомственные интеграции и шлюзы

Для исключения ручного сбора справок система интегрирована с ключевыми государственными сервисами Республики Узбекистан:

1. OneID (id.egov.uz)

Единая точка входа отельера. Автоматическое заполнение ИНН, ПИНФЛ руководителя, наименования юрлица и контактных данных без ручного ввода.

2. E-IMZO (e-imzo.uz)

Криптографическая подпись документов по стандарту O'z DSt 1092. Формирование открепленной подписи PKCS#7 / CMS для заявки и решения инспектора.

3. Платежные шлюзы (Click / Payme / Munis)

Автоматическая фиксация оплаты сбора за сертификацию по инвойсу с мгновенным переводом заявки в статус «Оплачено» и передачей в работу инспектору.

4. Soliq.uz и Кадастр РУз

Проверка действующего статуса юрлица, ОКЭД 55.10 (гостиницы), отсутствия налоговых арестов, проверка кадастрового номера и целевого назначения земли.

7.5. Нефункциональные требования и надежность

  • Доступность сервиса (SLA): Не менее 99.5% времени безотказной работы для публичного реестра и QR-верификатора.
  • Производительность реестра: Время холодного ответа страницы верификации ≤ 2.0 секунд при 1000 одновременных запросах.
  • Клиентская оптимизация фотоматериалов: Автоматическое сжатие изображений в WebP (макс. 1600px по широкой стороне) в браузере заявителя перед отправкой, сохраняющее EXIF-метаданные.
  • Антифрод и геолокация: Вычисление девиации координат съёмки относительно кадастрового пятна объекта по формуле Haversine с порогом ≤ 150 метров.
  • Неизменяемый журнал аудита: Реализация хеш-цепочки SHA-256 (Hash Chain) — каждая операция хеширует состояние предыдущей записи, гарантируя выявление любого изменения в БД.
